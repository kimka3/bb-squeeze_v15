## 1. 한 줄 요약

**변동성이 극도로 수축(squeeze)한 뒤 볼린저 밴드가 다시 팽창(expansion)하면서 밴드 바깥으로 이탈하는 순간을, SMA200 추세 방향과 일치할 때만 잡는 4시간봉 돌파 전략.** 숏은 즉시 진입, 롱은 돌파 후 "되돌림 재확인(retest)"을 기다린 뒤 진입한다. 포지션 크기는 가격이 아니라 **ATR 기반 손절거리와 계좌 위험률**로 정해진다.

---

## 2. 전략의 뼈대

```
확정된 4시간봉
   ↓
[지표]  BB(20, 2σ) · ATR(14 Wilder) · SMA200 + 5봉 기울기
   ↓
[국면]  squeeze (변동성 수축) → expansion (재팽창)
   ↓
[방향]  SMA200 위/아래 + 기울기 부호로 롱/숏 결정
   ↓
[진입]  숏: 즉시 / 롱: 최대 3봉 내 retest 성공 시
   ↓        (둘 다 "다음 4시간봉 시가"에 시장가)
[사이징] 위험금액 ÷ (ATR × 손절배수) = 수량, 이후 포트폴리오 한도로 축소
   ↓
[관리]  서버측 손절 + (숏) 2R 절반익절 → 본전이동 → 2ATR 추적손절
   ↓
[강제청산] 롱: BB 중앙선 이탈 또는 180봉 / 숏: 90봉
```

## 3. 지표 정의 (정확한 수식)

| 항목 | 정의 | 코드 |
|---|---|---|
| BB 중앙 | `SMA(close, 20)` | `close.rolling(20).mean()` |
| BB 표준편차 | **모집단** 표준편차 `ddof=0` | `close.rolling(20).std(ddof=0)` |
| BB 상·하단 | 중앙 ± `2.0 × σ` | |
| **BBW** | `(상단 − 하단) / 중앙` = `4σ / SMA20` | 밴드 폭의 *상대* 크기 |
| TR | `max(H−L, |H−C₋₁|, |L−C₋₁|)`, 첫 봉은 `H−L` | |
| **ATR** | TR의 Wilder EWM(14), `alpha=1/14, adjust=False` | 시드가 **첫 TR 값** |
| ATR% | `ATR / close` | 가격 수준에 중립적인 변동성 |
| SMA200 | `SMA(close, 200)` | |
| SMA200 기울기 | `SMA200[t] − SMA200[t−5]` | 부호만 사용 |

> ⚠ **ATR 주의점.** 원본은 `pandas.ewm(adjust=False)`를 쓰므로 **첫 TR 값이 시드**다. TradingView의 `ta.rma()`는 **SMA(14) 시드**라 값이 다르다. 그래서 Pine 이식본은 `ta.atr()`를 쓰지 않고 pandas 재귀식을 직접 구현했다(`f_wilder_adjust_false`).

### 3.1 백분위(percentile) — 이 전략의 핵심 장치

```python
# 최근 120개 값 중 "현재 값 이하"인 값의 비율 (동률 포함, 현재 값 자신 포함)
percentile = sum(v <= current for v in window_120) / 120
```

- 120개가 **모두 유효할 때만** 계산한다(`min_periods=120`). 워밍업을 줄이지 않는다.
- 현재 값을 포함하므로 최솟값은 `1/120 ≈ 0.0083`이다.
- TradingView의 `ta.percentrank()`는 **현재 봉을 제외**하고 `<` 비교에 0~100 스케일이라 **다른 값**이 나온다. 이식본은 직접 루프로 구현했다.

### 3.2 squeeze (변동성 수축)

```
core_squeeze[t] = (BBW 백분위[t] ≤ 0.20) AND (ATR% 백분위[t] ≤ 0.30)

squeeze_ready[t] = (t−5 … t−1 의 5개 봉 중 core_squeeze 가 참인 봉이 3개 이상)
```

**현재 봉은 세지 않는다.** 즉 "직전 5봉 동안 충분히 조용했는가"를 묻는 조건이고, 현재 봉은 그 정적을 깨는 봉이어야 한다.

### 3.3 expansion (재팽창)

```
expansion_ok[t] = (BBW[t] / BBW[t−3] − 1 ≥ 0.12) AND (BBW[t] > BBW[t−1])
```

3봉 전 대비 밴드 폭이 **12% 이상 넓어졌고**, 직전 봉보다도 넓어지는 중이어야 한다. 수축이 실제로 "끝났다"는 확인이다.

## 4. 진입 규칙

### 4.1 숏 (변형 `09_EXP_SLOPE`) — 확정봉 4조건 동시 충족

1. `squeeze_ready` = 참
2. `expansion_ok` = 참
3. `close < BB 하단` **그리고** `close < SMA200`
4. `SMA200 기울기(5봉) < 0`

→ 조건 충족 즉시 **다음 4시간봉 시가**에 시장가 숏.

### 4.2 롱 — 2단계 (돌파 → retest)

**1단계 setup (진입 아님):**
```
squeeze_ready AND expansion_ok AND close > BB 상단 AND close > SMA200 AND 기울기 > 0
```
이때 그 봉의 **BB 상단 값을 기준가로 저장**하고 유효기간 3봉을 준다.
**돌파봉 자체로는 절대 진입하지 않는다** (같은 봉 retest 금지).

**2단계 retest (진입):** setup 이후 최대 3개 확정봉 안에서 아래를 모두 만족하면 진입.
```
low  ≤ 기준가 × 1.005     ← 기준선까지 되돌아왔고
close > 기준가             ← 다시 위로 마감했고
close > open               ← 양봉이고
close > SMA200
SMA200 기울기 > 0
```
- 3봉 안에 못 채우면 setup 폐기.
- 대기 중 새 breakout이 나오면 기준가와 3봉 카운터를 **갱신**한다.
- 해당 종목에 포지션이 있으면 setup은 즉시 폐기된다.

### 4.3 진입 타이밍과 시효

신호는 **확정된 4시간봉**에서만 계산한다. 진입은 **그 다음 봉 시작 시점**에 시장가로만 시도하며, `max_entry_lateness_seconds = 120`초가 지나면 **추격하지 않고 포기**한다. (봇 재시작 후 몇 시간 늦게 뒤늦은 진입을 하는 사고를 막는 장치다.)

### 4.4 유니버스와 충돌 처리

- 롱: `BTC, ETH, SOL` (3종)
- 숏: `BTC, ETH, SOL, BNB, XRP, ADA, DOGE, LINK, LTC, BCH, AVAX` (11종)
- 같은 시각 다중 신호 → 위 숏 목록 **순서**가 결정론적 우선순위
- 같은 종목에 롱·숏 의도가 동시 발생 → **둘 다 건너뜀**

## 5. 포지션 사이징 — 이 전략에서 가장 중요한 부분

### 5.1 기준자산과 목표수량

```
E = min(거래소 계좌 총자산, strategy_equity_cap_usdc)      # 기본 1000 USDC

손절거리 = 신호봉 ATR × (롱 1.5 / 숏 1.0)
목표수량 = E × 진입위험률 ÷ 손절거리
```

즉 **"손절에 걸리면 E의 x%를 잃는다"**가 되도록 수량을 역산한다. 변동성이 크면 수량이 작아지고, 조용하면 커진다.

### 5.2 진입위험률 — 2% 오버라이드와 BTC 국면 필터

```
새 롱                         → E × 2%
새 숏, BTC 확정신호봉 종가 ≥ BTC SMA200  → E × 2% × 0.5 = E × 1%
새 숏, 그 외                   → E × 2%
```

- BTC가 강세 국면이면 **신규 숏만** 위험을 절반으로 줄인다. 강세장에서 숏 치는 것에 대한 페널티다.
- 미래 데이터나 진입 시점의 BTC 값은 쓰지 않는다. **신호봉 스냅샷**만 쓴다.
- **이미 열린 포지션은 BTC 국면이 바뀌어도 리사이징하지 않는다.** 신규 진입 정책이지 리밸런싱 규칙이 아니다.

### 5.3 포트폴리오 한도 (동시 적용, 순서 무관)

| 한도 | 값 | 효과 |
|---|---|---|
| 모든 포지션 잔여 초기위험 합계 | `E × 4%` | 신규 수량 축소 또는 거절 |
| 총 명목 노출 | `E × 5` | 저변동성 종목에서 실제로 걸린다 |
| 동시 포지션 수 | 6개 | 초과 시 거절 |
| 한도축소 하한 | 목표수량의 10% 미만이면 **거절** | 의미 없는 미니 포지션 방지 |
| 거래소 제약 | step 내림 → 최소수량/최소명목 미달 시 거절 | |
| 숏 추가 조건 | 절반익절 수량 < 최소수량이면 **진입 자체 거절** | |

부분청산 후 잔여 초기위험은 수량 비례로 줄어든다: `잔여위험 = 초기위험 × 현재수량 / 초기수량`.

> 총 명목 5배 한도는 생각보다 자주 걸린다. 숏 기준 `명목 = E × 2% × 가격 / ATR`이므로 `ATR% < 0.4%`면 5배 한도가 목표수량을 깎는다. 그런데 squeeze 셋업은 정의상 저변동성 구간이다.

## 6. 청산과 보호 주문

### 6.1 롱

| 규칙 | 내용 |
|---|---|
| 초기 손절 | 진입가 − `1.5 × 신호봉 ATR`, 전량 서버측 reduce-only |
| 추세 이탈 | 확정봉 **종가 < BB 중앙선** → 시장가 청산 |
| 시간 청산 | **180봉**(=30일) 보유 → 시장가 청산 |

롱에는 부분익절도, 추적손절도 없다. 손절 아니면 BB 중앙선 이탈 아니면 시간이다.

### 6.2 숏

| 규칙 | 내용 |
|---|---|
| 초기 손절 | 진입가 + `1.0 × 신호봉 ATR`, 전량 서버측 reduce-only |
| 부분익절 | `진입가 − 2 × 신호봉 ATR` (= **2R**)에서 **초기수량의 50%** |
| 본전 이동 | 익절이 일부라도 체결되면 잔여 TP 취소 + 손절을 **진입가 이하**로 제한 |
| 추적손절 | 매 확정봉마다 `지금까지의 최저 저가 + 2 × 현재봉 ATR`로 조임 |
| 시간 청산 | **90봉**(=15일) 보유 → 시장가 청산 |

**추적손절의 두 가지 중요한 성질:**
1. `최저 저가`는 **진입가로 시드**된다(`lowest_low = 진입 평균가`). 그래서 진입 직후부터 작동한다.
2. **절대 느슨해지지 않는다.** `new_stop = min(현재 손절, 후보)` — 더 타이트할 때만 갱신한다.
3. 추적 폭에 쓰는 ATR은 신호봉 ATR이 아니라 **매 봉의 현재 ATR**이다. 변동성이 커지면 자동으로 여유를 준다(단, 이미 조여진 값보다 느슨해지지는 않는다).

### 6.3 보유 봉 카운트

`bars`는 **진입봉 종가에 1**이 된다. 즉 `bars >= 90`은 진입봉 포함 90번째 4시간봉 종가에 청산이다.

## 7. 운영 안전장치 (Pine에는 이식되지 않는 부분)

전략 자체는 아니지만 봇 코드의 절반 이상이 여기에 쓰여 있다.

- **HALT 래치**: 미관리 포지션, 알 수 없는 활성 주문, 수량/방향 불일치, 손절 주문 부재, 서명 결과 불명 → 즉시 중단하고 신규 진입 금지
- **손절 < 청산가 검증**: 계획 손절이 거래소 청산가보다 먼저 오지 않으면 진입 거절
- **결정론적 `client_order_index`**: 중복 주문 방지, 재시작 안전
- **신규 진입 차단 오버레이**: 일일 손실 3%, 고점대비 낙폭 10% (자동 청산은 하지 않음)
- **최소 가용잔고 50 USDC, 최소 증거금 버퍼 1.5배**
- **state DB를 endpoint + account index에 영구 결합** — 다른 계정 재사용 거절

## 8. Pine Script 이식본 사용법

### 8.1 적용

1. TradingView 차트를 **4시간봉**으로 설정
2. Pine Editor → 새 전략 → `pine/bb_squeeze_v15_candidateA_risk2.pine` 내용 붙여넣기
3. Add to chart → 설정에서 심볼별로 조정
   - 롱 유니버스(BTC/ETH/SOL)가 아닌 심볼: **"롱 사용" 체크 해제**
   - 숏 유니버스 11종이 아닌 심볼: **"숏 사용" 체크 해제**
   - `BTC 국면 기준 심볼`: 차트 거래소에 맞게 (예: `BINANCE:BTCUSDT`)
   - `전략 사용자산 상한`: 봇의 `strategy_equity_cap_usdc`에 해당

### 8.2 기본 비용 설정

원 연구 가정(`research_design.json`)을 기본값으로 넣었다: **수수료 편도 0.05%**(`commission_value = 0.05`), 슬리피지 0.02%는 Pine의 `slippage`가 틱 단위라 0으로 두었다. 체감 슬리피지를 넣으려면 `slippage` 값을 심볼 틱 크기에 맞춰 직접 설정한다.

### 8.4 원본과의 알려진 차이 — 반드시 감안할 것

| # | 차이 | 영향 |
|---|---|---|
| 1 | **교차-심볼 포트폴리오 한도 미재현.** TradingView 전략은 심볼당 독립 실행이라 4% 공유위험·6포지션 한도가 사실상 무력하고 5배 명목 한도만 단일 포지션 기준으로 걸린다 | 11개 심볼을 따로 돌려 합산하면 **원 봇보다 위험이 과대평가**된다 |
| 2 | **종가 규칙 청산의 체결 시점.** 봇은 봉 마감 ~20초 후 시장가, Pine 기본값은 다음 봉 시가 | 4H 유동 시장에서는 작지만 0은 아니다 |
| 3 | **숏 부분익절 주문 유형.** 봇은 take-profit 시장가 트리거(슬리피지 1%), Pine은 지정가 | Pine 쪽이 **낙관적** |
| 4 | **진입봉 보호.** 실제 평균체결가는 다음 봉에야 알 수 있어, 진입봉 동안은 신호봉 종가 기준 임시 손절이 걸리고 진입봉 종가에 실제 평균가 기준으로 갱신 | 손절 위치가 진입봉 동안 미세하게 다르다 |
| 5 | **같은 봉 청산 후 재진입.** 봇은 한 확정봉에서 청산이 끝나면 같은 봉 신호로 재진입 가능, Pine은 그 봉을 건너뜀 | 드문 엣지 케이스 |
| 6 | **펀딩비 미반영.** 원 연구는 Binance 실측 펀딩을 반영했다 | 숏 편향 전략이라 방향성 있는 차이 |
| 7 | **운영 안전장치 전부 미이식** (HALT, 청산가 검증, 재조정, 일일손실 차단 등) | 백테스트는 이 장치들이 막았을 사고를 겪지 않는다 |

## 9. 위험 경고 (원본 README에서 그대로 옮김)

> **현재 2% 설정은 원 백테스트 성과가 아니다.** 원 검토·백테스트는 거래당 위험 **1.25%**, BTC bullish 신규 숏 **0.625%**를 사용했다. 현재 기본값인 2%/1% 조합은 성과, tail loss, 청산 가능성, MDD가 **재검증되지 않았다.** 과거 약 **−40~−45% MDD**를 단순히 `2 ÷ 1.25`배로 환산해서도 안 된다. 동시 포지션, 4% 공유위험 cap, 5배 gross cap, 최소 주문, 슬리피지, 갭, 청산이 상호작용하므로 실제 손실과 낙폭은 **선형 비례보다 더 크게 악화될 수 있다.**

> **데이터 한계:** 원 연구의 "Lighter" 결과는 실제 Lighter 시세가 아니라 **Binance 가격·펀딩 데이터와 가정된 수수료**를 사용했다.

> `strategy_equity_cap_usdc`는 "이 전략이 크기 계산에 사용할 최대 자산"이지 **손실 한도가 아니다.** 4% 공유위험 cap도 "갭·슬리피지·청산 손실을 4%로 제한한다"는 뜻이 아니다.
