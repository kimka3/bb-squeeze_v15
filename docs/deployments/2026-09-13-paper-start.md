# 페이퍼 캠페인 배포 및 시작 기록

상시 Linux VPS에 개선된 코드를 배포하고 공개 시세를 이용하는 페이퍼 캠페인을 시작했다. 이 기록은 서버에서 확인한 시작 상태이며, 전체 관측 기간의 완료나 전략 성과 검증을 의미하지 않는다.

**이 문서의 날짜·시각·버전·횟수·포트 등 배포 관련 숫자는 신규 서버 관측값 또는 적용한 운영 설정이다. 인수인계 문서에 없음.** 기존 인수인계 문서의 백테스트 성과와 구분한다.

2026-09-12 23:24:20.367 UTC 상태를 확인했다.

| 항목 | 당시 관측값 |
|---|---|
| 성공한 시세 폴링 | `successful_polls=4` |
| 저장된 호가 관측 | `observations=2` |
| HALT | 없음 |
| 폴링·봉 처리·호가 관측 오류 | 없음 |
| 모의 체결 | 0건 |

systemd 기록에서 2026-09-12 23:23:13 UTC 서비스 중지와 23:23:16 UTC 재시작을 확인했다. 같은 시기에 `apt.systemd.daily` 활동이 관측되었으나, 이 기록만으로 중지 원인을 단정하지 않는다. 재시작 후 기존 캠페인 ID, 고정 종료 시각 및 저장 상태를 유지하고 작업 프로세스가 재개된 것을 확인했다. 이 확인이 중지 구간의 시장 데이터를 빠짐없이 관측했다는 뜻은 아니다.

초기 자동 업데이트가 새 커널과 libc 설치를 완료하고 재부팅을 요구한 사실도 확인했다. 모의 포지션과 체결이 없는 상태에서 23:28:07 UTC 정상 중지·저장 후 서버를 재부팅했다. 23:29:51 UTC 재접속 검증에서 새 커널 `6.8.0-139-generic`, NTP 동기화 정상, 재부팅 필요 표시 해제를 확인했다. 서비스는 수동 시작 명령 없이 자동 기동했고, 기존 캠페인 ID와 종료 시각을 유지했다. 작업 프로세스는 23:28:44 UTC 재개됐으며, 이후 성공한 폴링 9회·호가 관측 3회와 오류·HALT 없음이 기록됐다. 이 재부팅 구간도 실제 관측한 시간으로 간주하지 않는다.

**모의 체결이 아직 0건이므로 수익률·MDD·체결 품질에 관한 결론을 내릴 수 없다.** 초기 오류가 없었다는 사실과 전체 캠페인의 안정성은 구분한다.

## 적용한 접속 및 권한 설정

- SSH 인증은 `AuthenticationMethods publickey`로 제한했다. `PasswordAuthentication no`, `KbdInteractiveAuthentication no`를 확인했다.
- root의 비밀번호 접속은 금지하고, 운영체제 유지보수와 복구를 위한 키 접속은 유지했다. 설정은 `PermitRootLogin prohibit-password`이며 유효 설정 출력에서 동의어인 `without-password`로 표시될 수 있다.
- `bbadmin`의 sudo 권한은 root 소유 `/usr/local/sbin/bb-paper-control`의 `status`, `report`, `logs`, `start`, `stop`, `restart`에만 한정했다. `NOPASSWD ALL`은 부여하지 않았다.
- 상태·보고서를 읽는 Python은 `bbpaper` 권한으로 실행한다. 서비스 제어와 로그 조회는 고정된 서비스 및 인자로 제한한다.
- UFW는 IPv4·IPv6의 SSH 포트 22 인바운드만 허용하고, 아웃바운드는 허용한다.

이 공개 기록에는 접속 주소, 키 경로·내용·지문, 개인 식별 정보, 자격 증명 및 원시 운영 로그를 포함하지 않는다.

## 남은 운영 및 평가 조건

- 외부 장애 알림 채널은 아직 설정하지 않았다. 서비스 자동 시작·재시작 기능이 운영자에게 장애 메시지를 보내는 것은 아니다. 운영자는 최근 데이터 시각, HALT·오류, 재시작 및 디스크 상태를 확인해야 한다.
- 공개 펀딩 응답의 방향·단위 의미가 확인되지 않은 항목은 원자료를 보존하고 미해결로 남긴다. 이런 항목이 발생하면 `performance_complete=false`, `equity_excludes_unresolved_funding=true`를 확인하고 잔액을 완전한 펀딩 차감 후 성과로 해석하지 않는다.
- 실행 버전·의존성·설정과 캠페인 상태를 보존한다. 운영체제 갱신이나 재부팅 후에도 작업 프로세스와 최근 데이터 기록이 실제로 재개됐는지 확인한다.
- 종료 시에는 성과뿐 아니라 데이터 누락, 관측 지연, 중단, 부분체결 및 펀딩 미해결 범위를 함께 평가한다. 체결 표본이 부족하면 기간이 끝나도 해당 실행 가설은 미검증 상태다.
- 실주문 실행 차단을 유지한다. 이 캠페인 시작 또는 종료가 실거래 전환 승인을 의미하지 않는다.

설치·조회·중지 및 결과 보관 절차는 [페이퍼 운영 문서](../paper-operations.md)를 참고한다. 해당 문서의 배포 전 준비 상태와 실제 시작 여부는 이 배포 기록을 구분하여 읽는다.
