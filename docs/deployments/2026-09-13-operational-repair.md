# 확정 봉 수집·재시도·관측 기록 운영 수정

사용자가 당일 운영 오류 수정을 승인하여 실행 코드 `78ff5a96e913697e01831aaea60953f8bfa5bd5a`를 기존 페이퍼 캠페인에 반영했다. 아래 시각·횟수·지연·버전은 **인수인계 문서에 없음 — 이번 관측·검증·운영 설정**이다.

## 수정한 문제

- 전체 종목의 봉 요청에 같은 종료 시각을 지정하고 기존 정상 입력 길이인 확정 봉 599개를 유지한다. 종목마다 현재 진행 중인 봉의 응답 여부가 달라도 입력 창이 달라지지 않는다. 실제 누락·오래된 최신 봉·내부 공백은 거부하며 임의 교집합이나 값 채우기를 하지 않는다. 기존 오류의 정확한 응답 배열은 보존되지 않아 과거 불일치의 세부 원인은 확정하지 않는다.
- 봉 실패 재시도를 기존 시세 점검 주기에서 분리했다. 대기는 5·10·20초 이후 최대 30초다. 기존 진입 허용 시간과 지연된 신규 진입 차단은 유지한다. 조회가 봉 마감 경계를 넘어 끝나도 반환된 봉 시각에 따라 다음 봉을 수집한다.
- 관측 실패·복구 증거, 지연된 봉, 재시작 공백을 영속 기록한다. 거래가 없던 구간의 API 실패도 보고서에서 제외하지 않는다. 과거 저널에 없는 정확한 장애 시작·복구 시각은 만들지 않는다. 실제 처리되지 않은 봉을 처리 성공으로 집계하지 않는다.
- 캠페인의 지문 검사는 계속 적용한다. 승인된 운영 소스 수정에 한해 정상 일시 정지·잠금·예상 커밋·고정 설정을 검사하는 명시적 수정 절차와 원본 보존 이력을 추가했다.

전략, BCH 제외 종목 구성, 위험비율, 진입·손절·익절, 비용·체결 모형, 가상자본과 패키지는 변경하지 않았다. Git diff의 실행 소스 변경은 `feed.py`, `run.py`, `runtime_health.py`, `revision.py`에 한정된다.

## 검증과 실제 반영

- Windows와 실제 VPS 모두 전체 테스트 **169개 통과**.
- VPS 별도 검증 경로에서 공개 데이터 조회: **10개 종목 모두 같은 확정 봉 599개**, 최신 봉 시각 일치. 이 확인은 당시 정상 조회이며 다음 실제 마감 경계의 개선 효과를 이미 관측했다는 뜻은 아니다.
- 서비스를 일시 정지하고 캠페인 전체를 압축 백업했다. 수정 도구는 원래 설정과 전체 상태 파일의 전후 해시가 동일함을 검증하고, 원본·신규 캠페인 manifest와 완료 영수증을 `revisions/`에 보존했다.
- 실행 지문 갱신: **2026-09-13 12:26:15 UTC**. worker 재개: **12:26:16 UTC**.
- 실제 검증: **12:27:18 UTC / 21:27:18 KST**. worker 생존, 시세 poll 갱신과 호가 관측 재개, HALT·청산 잔량 없음. 당시 모의 포지션·체결은 모두 0이다.
- 이전 상태 저장부터 새 관측 기록 시작까지 **3.361초**를 재시작 관측 공백의 보수적 상한으로 기록했다. 실제 거래소 장애 지속 시간으로 해석하지 않는다.

캠페인 `f29438d6bd3546a49e4ca938e9c7b217`의 최초 시작은 **2026-09-12 23:21:39 UTC**, 종료는 **2026-10-10 23:21:39 UTC / 2026-10-11 08:21:39 KST**로 유지된다. 보수 중단 때문에 기간을 다시 시작하거나 연장하지 않았다.

## 결과 해석과 후속 점검

과거 지연 봉 4회, poll 실패 15회, 봉 오류 4회, 호가 관측 오류 1회를 복원·보존했다. 최초 기동 당시 과거 봉 처리는 예정된 마감 시각의 지연과 별도 구분한다. 과거 실패 표본의 첫 시각부터 마지막 시각까지 840.585초이며, 정확한 API 장애 기간은 미상이다.

검증 시 `ledger_performance_complete=true`, `observation_coverage_complete=false`, 종합 `performance_complete=false`였다. 앞의 값은 기존 모의 장부 측정 범위의 표시로, 무체결 상태에서 체결·펀딩이나 전략 수익성을 입증하지 않는다. 마지막 두 값은 이미 발생한 관측 공백을 정직하게 표시한다. 수정 전후 버전과 공백을 최종 평가에서 구분한다.

일일 점검은 기존 한국시간 오후 9시 일정을 유지한다. 새 오류·새 지연·실제 진입 차단 후보·장기 공백을 확인하며, 기존 누적 오류를 새로운 장애로 반복 통보하지 않는다. 다음 실제 봉 마감에서 수정 효과를 확인해야 한다. 거래소 자체의 향후 API 장애가 제거됐다고 주장하지 않는다.
