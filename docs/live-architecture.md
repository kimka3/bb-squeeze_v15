# BB Squeeze A (거래당 위험 2%) — Lighter 자동매매 아키텍처

작성 2026-09-12. Lighter 사실 확인은 같은 날 공식 문서와 공개 API 응답 기준입니다.
이 문서가 구현의 기준이며, 코드와 같은 저장소에서 버전 관리합니다.

---

## 1. 한 문단 요약

이 전략의 의사결정은 **4시간에 한 번**만 일어나고, 스탑·부분익절은 **가격이 닿을 때마다** 일어납니다.
이 둘을 하나의 루프에 섞으면 백테스트와 어긋납니다. 따라서 느린 루프(4시간 경계)는 봇이 담당하고,
빠른 루프(스탑/익절)는 **Lighter의 네이티브 조건부 주문에 위임**합니다. 봇이 죽어도 포지션은 보호됩니다.
그리고 백테스트와 실거래가 **같은 결정 코드**를 호출하도록 코어를 분리하는 것이 가장 중요한 설계 결정입니다.

## 3. 전략이 실행기에 요구하는 것

### 두 개의 시계

| | 주기 | 하는 일 |
|---|---|---|
| **느린 루프** | 4시간 봉 마감 | 지표·신호 계산, 포트폴리오 배분, 진입, 추적스탑 갱신, 봉마감 청산 예약 |
| **빠른 루프** | 가격 도달 시 | 손절, 2R 부분익절, 익절 후 본전 스탑 |

핵심은 **추적스탑이 틱 단위가 아니라 봉 단위**라는 점입니다. `frontier_engine.py`의 해당 블록은
4시간 봉 마감에만 실행되고, `tighten_stop`은 단조(한 방향)입니다. 주석도 *"monotone trails become
active on next bar"*라고 명시합니다. 즉 **스탑 가격은 4시간에 한 번만 바뀌고 그 사이에는 고정**입니다.
이것이 네이티브 스탑 주문에 위임할 수 있는 이유입니다.

### 청산 사유의 두 분류

| 분류 | 사유 | 백테스트 동작 | Lighter 매핑 |
|---|---|---|---|
| **가격 트리거 (봉 내부)** | `STOP`, `TP2R`, `BE_AFTER_TP` | 봉 내부에서 즉시 | **네이티브 SL / TP (reduce-only)** |
| **신호 트리거 (다음 봉 시가)** | `BB_MID`, `TIME`(숏 90봉·롱 180봉) | `pending_exit` → 다음 봉 시가 | 4시간 경계에서 **시장가 reduce-only** |

이 분류가 아키텍처를 가릅니다. 섞으면 안 됩니다.

### 포지션 상태 기계 (숏)

```
       진입 (시장가)
          │
          ▼
    ┌───────────┐   mark ≥ entry+1.0·ATR    ┌──────┐
    │  OPEN     │──────────────────────────▶│ 종료 │
    │  SL @ 1R  │                            └──────┘
    │  TP @ 2R  │   mark ≤ entry-2.0·ATR
    └───────────┘──────────────┐
          │                     ▼
          │              50% 체결 → SL을 본전으로 정정
          │                     │
          │                     ▼
          │              ┌──────────────┐  mark ≥ entry  ┌──────┐
          │              │ HALF_OPEN    │───────────────▶│ 종료 │
          │              │ SL @ breakeven│                └──────┘
          │              └──────────────┘
          ▼
   4시간 봉 마감마다: SL을 min(현재SL, lowest + 2.0·ATR)로 단조 정정
                      90봉 경과 시 다음 시가 시장가 청산
```

롱은 더 단순합니다. SL은 `entry − 1.5·ATR` 고정(추적 없음), 4시간 종가가 BB 중앙선 아래면
다음 시가 시장가 청산, 180봉 시간 청산.

## 4. 가장 중요한 설계 결정: 결정 코어를 백테스트와 공유한다

라이브용으로 전략을 **다시 구현하면 괴리는 반드시 생깁니다**. 대신 `frontier_engine.run()`의
봉 단위 본문을 순수 함수로 추출해 백테스트와 실거래가 같은 코드를 호출하게 합니다.

```python
# core/decide.py — I/O 없음, 난수 없음, 시계 없음. 전부 인자로 주입.

def on_bar_close(state: EngineState, bars: dict[str, Bar], equity: float) -> Decisions:
    """4시간 봉 마감 시점의 모든 결정. 백테스트와 실거래가 동일하게 호출한다.

    반환: 청산 예약, 진입 지시(정규 순서), 스탑 정정 목록.
    """

def apply_fill(pos: Position, fill: Fill) -> Position:
    """체결 하나를 포지션 상태에 반영. TP 체결 시 본전 스탑으로 전이하는 규칙이 여기 있다."""
```

- **백테스트**는 `on_bar_close()`를 과거 봉에 순차 호출하고, 봉 내부 터치를 `simulate_intrabar()`로
  만들어 `apply_fill()`에 먹입니다.
- **실거래**는 `on_bar_close()`를 실제 4시간 경계에 한 번 호출하고, 거래소 체결 이벤트를
  그대로 `apply_fill()`에 먹입니다.

`simulate_intrabar()`만 백테스트 전용이고, 그 자리를 실거래에서는 거래소의 SL/TP가 대신합니다.
**상태 전이 규칙은 한 벌만 존재합니다.** 이 구조가 아니면 "백테스트에서는 되는데 실거래에서는 다른"
문제를 영원히 쫓게 됩니다.

기존 코드에서 이 추출은 어렵지 않습니다. `frontier_engine.run()`의 루프 본문이 이미
`펀딩 → 예약청산 → 진입 → 봉내부 → 추적갱신 → 신호생성` 순서로 명확히 나뉘어 있습니다.

## 6. 4시간 경계 시퀀스

백테스트 루프의 순서를 그대로 옮깁니다. 순서가 결과를 바꾸므로 임의로 바꾸면 안 됩니다.

```
T-0 = UTC 00/04/08/12/16/20 정각

T+0s    경계 도달. 아직 아무것도 하지 않는다.
T+5~15s Binance에서 방금 마감된 4시간 봉 11개 심볼 확정 수신.
        ├ 봉이 없거나 늦으면 → 이번 봉 건너뛰고 경보. 추측으로 진행하지 않는다.
        └ 지표·신호 재계산 (MA200 때문에 최소 200봉 워밍업 필요)
T+15s   정합성 검사: Lighter의 실제 포지션·미체결주문 ↔ 내부 상태
        └ 불일치 → 즉시 중단, 신규 진입 금지, 기존 SL은 유지, 사람 호출
T+16s   on_bar_close() 호출 → Decisions
T+17s   ① 예약 청산 먼저 실행 (BB_MID, TIME) — 시장가 reduce-only
        ② 진입을 정규 순서(BTC,ETH,SOL,BNB,XRP,ADA,DOGE,LINK,LTC,BCH,AVAX)로 순차 실행
           └ 각 진입마다 위험예산 잔량을 재계산. 병렬 실행 금지.
        ③ 체결 확인 후 실제 체결수량 기준으로 SL/TP 조건부 주문 등록
        ④ 기존 포지션의 추적스탑 정정 (단조: 유리한 방향만)
T+30s   저널에 봉 단위 결정 기록 + 스냅샷
```

**①을 ②보다 먼저** 하는 이유: 백테스트가 그렇게 하기 때문입니다(`Execute all prior-close exits
before any new entries`). 청산으로 풀린 위험예산이 같은 봉의 신규 진입에 쓰입니다.

**진입을 순차로** 하는 이유: `room = 자산×4% − Σ기보유위험`이 매 진입마다 줄어듭니다.
병렬로 쏘면 한도를 초과하거나 배분이 백테스트와 달라집니다.

## 7. 주문 매핑과 안전 규칙

### 진입
시장가 IOC. **위험 회계는 항상 실제 체결수량 기준**으로 기록합니다.
백테스트는 의도수량이 곧 체결수량이지만 실거래는 아닙니다.
부분 체결 시 `initial_risk = 실제체결수량 × unit`으로 기록하고 SL도 그 수량에 맞춥니다.

### 보호 주문 — 포지션이 무방비인 순간을 만들지 않는다

진입 체결 직후 두 주문을 등록합니다.

| 주문 | 수량 | 가격 | 옵션 |
|---|---|---|---|
| Stop-Loss | 포지션 **전량** | 숏 `entry + 1.0·ATR` / 롱 `entry − 1.5·ATR` | reduce-only |
| Take-Profit (숏만) | 포지션의 **50%** | `entry − 2.0·ATR` | reduce-only |

TP가 체결되면 SL을 본전 가격으로 **정정(amend)**합니다. 여기서 중요한 점:
SL은 reduce-only이고 수량이 잔여 포지션 이상이므로, **정정이 늦어져도 포지션은 계속 보호됩니다.**
취소 후 재등록이 아니라 정정을 쓰고, 정정 실패 시에도 기존 SL이 남아 있어야 합니다.
(`거래소가 amend를 지원하지 않으면` 신규 SL 등록 → 성공 확인 → 구 SL 취소 순서. 반대 순서 금지.)

### 추적스탑
4시간 경계에서만 정정. 단조성(`tighten_stop`)을 실행기에서도 강제합니다.
정정 요청 가격이 현재 SL보다 불리하면 **요청 자체를 버립니다**. 코어가 이미 단조를 보장하지만,
실행기에서 한 번 더 막는 것이 재시도·순서뒤바뀜에 대한 방어가 됩니다.

### 멱등성
클라이언트 주문 ID를 결정적으로 생성합니다: `hash(bar_timestamp, symbol, purpose, seq)`.
재시도해도 같은 ID가 나오므로 거래소가 중복을 걸러냅니다.
(`client_order_index`의 허용 범위를 먼저 확인해 해시를 그 범위로 접어야 합니다.)

## 8. 상태 관리와 재시작

**저장소는 append-only 이벤트 저널**입니다. 현재 상태는 저널 재생으로 복원합니다.
`(봉 시각, 의도 ID, 클라이언트 주문 ID, 거래소 응답)`을 기록하면, 봇이 배분 도중 죽어도
재시작 후 "어디까지 했는지"를 알 수 있습니다.

재시작 절차:
1. 저널 재생 → 내부 상태 복원
2. Lighter에서 실제 포지션·미체결주문 조회
3. **대조.** 일치하면 재개, 불일치하면 **중단하고 사람을 부릅니다.**

불일치를 자동으로 "치유"해서 주문을 내지 않습니다. 최대 6개 포지션짜리 전략에서
자동 복구 로직의 버그 위험이 수동 확인 비용보다 큽니다.

## 9. 안전장치

| 감시 항목 | 임계 | 조치 |
|---|---|---|
| Binance 봉 지연/결측 | 경계 후 60초 | 이번 봉 건너뜀, 경보 |
| 정합성 불일치 | 즉시 | **중단** · 신규 진입 금지 · SL 유지 · 호출 |
| 증거금 비율 | 유지증거금의 3배 미만 | 신규 진입 금지 |
| 증거금 비율 | 유지증거금의 2배 미만 | 경보 + 수동 개입 대기 |
| 주문 거부 연속 | 3회 | 해당 심볼 중단 |
| Binance ↔ Lighter mark 괴리 | 심볼별 임계 초과 | 해당 심볼 신규 진입 금지 |
| WS 연결 끊김 | 30초 | 재연결, REST 폴백으로 상태 확인 |

**킬스위치가 해서는 안 되는 일: 모든 주문 일괄 취소.**
SL을 취소하면 포지션이 무방비가 됩니다. 킬스위치는 *진입 측만* 멈추고
보호 주문은 반드시 남깁니다. 포지션을 실제로 닫으려면 그것은 별도의 명시적 명령입니다.

**전용 서브계정 사용을 권장합니다.** Standard 계정은 서브계정 4개를 허용하고 마진은 계정 단위
교차입니다. 전략을 전용 서브계정에 두면 자산 = 전략 자산이 되어 회계가 명확해지고,
다른 활동의 손익이 이 전략의 위험예산을 오염시키지 않습니다.

## 11. 신호 데이터는 Binance를 씁니다

Lighter에도 캔들 엔드포인트가 있지만, 신호는 **Binance 4시간 봉**으로 계산할 것을 권장합니다.

- 지표 전체(BB 20·2, ATR 14, MA200, rvol 20, 120봉 백분위 스퀴즈)가 Binance 데이터로 검증됐습니다.
- Lighter의 BTC 시장은 `created_at` 기준 2025-01에 생성됐습니다. MA200(4시간 기준 약 33일)은
  충족하지만, 백테스트가 본 2021년부터의 레짐은 Lighter에 존재하지 않습니다.
- 무료 수수료 백테스트 자체가 **Binance 가격·펀딩에 수수료만 0으로 둔 것**입니다.
  실제 Lighter 체결 백테스트가 아닙니다. 신호를 Lighter 가격으로 바꾸면 검증된 적 없는 입력이 됩니다.

단, **스탑 가격은 Lighter 체결가에 앵커링**합니다. ATR은 거리이므로 Binance에서 가져오되,
절대 가격은 `Lighter 실제 체결가 ± ATR 거리`로 잡습니다. 백테스트도 동일한 구조입니다
(`stop = px ± unit`, `px`는 실제 체결가).

두 거래소 종가 괴리를 매 봉 기록하고, 임계를 넘으면 해당 심볼 진입을 막습니다.

지연·mark 트리거가 들어간 실거래 검증이 아닙니다. 2단계 이후가 필요합니다.
