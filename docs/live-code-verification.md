## 3. 불일치 — 전 구간 게이트가 깨져 있습니다 ★

**기본값 400봉은 통과하지만 전 구간은 실패합니다.**

| 커밋 | 일치 | 선택 | 사이징 잔차 |
|---|---|---|---|
| `a13728f` (분기점) | **393/393** | PASS | 1.562e-10 |
| `13cefb23` (10-20) | 393/393 | PASS | 1.562e-10 |
| **`b1e55e74` (10-20 21:54)** | **380/393** | **FAIL** | **6.458e-01** |
| 이후 7개 커밋 전부 | 380/393 | FAIL | 6.458e-01 |
| `9a4fb8f` (tip) | 380/393 | FAIL | 6.458e-01 |

**원인 커밋: `b1e55e74` "Preserve dispatch evidence and independent position recovery"**

### 반증 시도 — 전부 실패

게이트 자신이 *"잔차가 ReplayBroker의 현금 원장 탓일 수 있다"*고 경고하므로 확인했습니다.

- 하네스(`replay.py`) 변경은 `AccountState`에 **필드 2개 추가뿐**이고 `equity()`를
  건드리지 않습니다 (`partial_taken`, `execution_changes_verified=True`)
- **같은 하네스로 `a13728f`는 통과**합니다 — 표본도 동일(백테스트 393건)
- `ReplayBroker`는 `execution_changes_verified=True`라 새 검증 경로가 막는 것도 아닙니다

### 기전

실거래 경로를 계측한 결과 **HALT 0회, 오류 0건**입니다. 유일한 스킵 사유는
**`cap` 303회**입니다.

즉 충돌이 아니라 **자산(equity) 계산이 어긋나 위험한도가 다른 지점에서 걸리는**
것이고, 종목 불일치는 그 하류입니다. 불일치 패턴이 이를 뒷받침합니다 —
같은 봉에서 다른 종목(`1641441600000`: 백테스트 XRP vs 실거래 DOGE), 또는
같은 종목이 한 봉 차이(`1683403200000` vs `1683417600000`).

전략 파라미터는 멀쩡하므로 **자산 조회·귀속 경로**를 봐야 합니다.
`b1e55e74`는 `strategy_broker.py`(+408), `trader.py`(+250)를 바꿨습니다.

### 과정 문제

`b1e55e74`는 **테스트 파일 15개를 추가했는데 Stage-1 게이트 테스트는 없습니다.**
게이트를 깬 커밋이 게이트를 돌리지 않았습니다. 기본값 400봉으로는 지금도
통과하므로 드러나지 않습니다.

## 4. Vultr에서 해야 할 확인 ← 남은 작업

클라우드 세션은 그 박스에 닿을 수 없어서 **실제로 배포된 코드를 못 봤습니다.**
§2·§3은 전부 "깃허브에 있는 codex tip" 기준입니다.

### 4.1 올바른 파이썬 찾기

봇이 돌고 있으니 numpy가 있는 파이썬이 있습니다. 보통 venv이고, 서비스 정의가
가장 확실합니다.

```bash
systemctl list-units --all | grep -iE 'bb|squeeze|lighter|live'
systemctl cat <유닛이름>      # ExecStart = 파이썬, WorkingDirectory = 배포 경로
```

레포 안 venv를 쓰는 경우:

```bash
ls -d */bin/python* .venv/bin/python* 2>/dev/null
```

### 4.2 배포된 커밋과 게이트

```bash
cd <WorkingDirectory>
git log --oneline -1          # 배포된 커밋 — 이게 가장 중요
git status --short            # 커밋되지 않은 로컬 수정이 있는지
<파이썬> src/live/replay.py --bars 99999 2>&1 | tail -15
```

### 4.3 결과 해석

| 출력 | 의미 | 조치 |
|---|---|---|
| `393 matched` / `PASS` | 배포된 코드는 `b1e55e74` **이전** | 그 커밋 이후를 올리지 말 것 |
| `380 matched` / `FAIL` | §3 회귀가 **실거래에 들어가 있음** | 증액 전 반드시 수정 |
| 그 외 숫자 | 깃허브에 없는 코드가 돌고 있음 | `git log`·`git status`로 추적 |

`git log`가 `9a4fb8f`가 아니면 §2·§3 결론을 그 커밋 기준으로 다시 봐야 합니다.

## 6. 그 외 실거래 쪽에 없는 것

1. **END가 아직 2026-09-01입니다.** 2026-11-09까지 연장한 백테스트(수수료 0 기준
   CAGR 39.59%, 새 구간 69.8일 -13.21%)가 거기 없습니다. 그 박스에서 백테스트를
   돌리면 옛 44.75%가 나옵니다.
2. **실측 슬리피지 연구가 없습니다.** `slippage_of` 훅, `cost_study.py`, 용량 곡선,
   유니버스 사다리가 전부 백테스트 계보에만 있습니다. 즉 **운용 중인 시스템은
   "자본이 커지면 수익구조가 망가진다"는 결론(자산 100k CAGR 31%, 1M -2.5%)을
   모릅니다.** 소액 테스트 중에는 무해하지만 증액 판단에는 필수입니다.
3. **www.binance.com 폴백이 제거됐습니다.** codex의 `BINANCE_HOSTS`는
   `fapi.binance.com` 하나뿐입니다(호스트 주입은 가능). 제가 그 호스트를
   "문서화된 공개 API가 아니다"라고 단 유보를 반영한 변경으로 보이며 합리적입니다.
   단, 451이 나오는 지역으로 옮기면 봉 수집이 실패합니다.
