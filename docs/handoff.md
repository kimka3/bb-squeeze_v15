이 파일 하나를 ChatGPT에 업로드하거나 붙여넣으면 지금까지의 맥락 전체가 전달됩니다.
파일 시작에 아래를 덧붙이면 대화를 바로 이어갈 수 있습니다.

> 첨부한 문서는 내가 진행 중인 암호화폐 자동매매 프로젝트의 인수인계 기록이다.
> 전제를 다시 묻지 말고 이 문서의 결론을 출발점으로 삼아라. 숫자를 인용할 때는
> 이 문서에 있는 값만 사실로 쓰고, 없는 값은 "문서에 없음"이라고 밝혀라.

### ChatGPT에서 **할 수 있는 것**

- 전략 설계·위험 관리 논의, 다음 단계 판단
- 측정 결과의 해석, 반증, 대안 설계
- 코드 리뷰(코드를 붙여넣는 경우), 새 모듈 초안 작성

### ChatGPT에서 **할 수 없는 것** (중요)

- **백테스트 재실행 불가.** 원천 데이터(2021-01~2026-08 Binance 4시간봉·5분봉·펀딩)가
  리포지토리에 있고 용량이 큽니다. 이 문서의 성과 숫자는 재현이 아니라 **인용**해야 합니다.
- **호가 측정 불가.** Lighter/Hyperliquid/Binance 실시간 오더북을 읽어야 나오는 수치입니다.
- **페이퍼 실행 불가.** 실행은 사용자 머신에서 이루어집니다(§8).

즉 ChatGPT는 **판단·설계·검토**에는 쓸 수 있지만 **측정·검증**에는 쓸 수 없습니다.
새 숫자가 필요하면 리포지토리에서 해당 스크립트를 돌려야 합니다.

## 1. 전략 정의

### 1.1 개요

BB Squeeze A안. 볼린저밴드 스퀴즈 이탈을 4시간봉으로 잡는 추세추종 전략입니다.
**숏 편중**입니다 — 전체 427건 중 373건(87.4%)이 숏입니다.

| 항목 | 값 |
|---|---|
| 시간 프레임 | 4시간봉 (신호 확정 후 **다음 봉 시가** 진입) |
| 표본 기간 | 2021-01-01 ~ 2026-08-31 (68개월) |
| 초기자금 | 100,000 USDT |
| 백테스트 유니버스 | 11종목 |
| 실거래 유니버스 | 10종목 (BCH 제외, §6.4) |

### 1.2 위험 관리 (2026-09-11에 1.25% → 2%로 상향)

| 항목 | 값 |
|---|---|
| **거래당 개별 위험** | **2.0%** |
| BTC SMA200 위 국면의 신규 숏 | 1.0% (절반) |
| 총 초기 위험 한도 | 4% |
| 총 명목 노출 한도 | 5배 |
| 동시 보유 한도 | 6개 |
| 진입 우선순위 | canonical |

위험 예산 = 초기 손절 거리 × 수량. **갭·슬리피지·수수료·펀딩을 포함한 절대 손실
상한이 아닙니다.** 총 한도는 신규 진입 크기를 정할 때만 적용하며, 이미 보유한
포지션을 강제로 줄이지 않습니다.

### 1.3 종목

```
BTCUSDT ETHUSDT SOLUSDT BNBUSDT XRPUSDT ADAUSDT
DOGEUSDT LINKUSDT LTCUSDT BCHUSDT(실거래 제외) AVAXUSDT
```

**BTC는 제외할 수 없습니다.** SMA200 국면 필터가 BTC 종가를 읽기 때문이며,
설정 코드에서 제외를 거부하도록 막아뒀습니다.

### 1.4 청산 규칙 — 두 분류로 나뉩니다

이 구분이 자동매매 설계 전체를 결정합니다.

| 분류 | 사유 | 실행 시점 | 거래소 위임 |
|---|---|---|---|
| **가격 트리거 (봉 내부)** | STOP, TP2R, BE_AFTER_TP | 즉시 | **가능** — 네이티브 SL/TP 주문 |
| **신호 트리거 (봉 마감)** | BB_MID, TIME | 다음 봉 시가 | 불가 — 봇이 직접 |

추적스탑은 **4시간봉 마감에만, 단조 증가(숏이면 단조 감소)로만** 갱신됩니다.
이 단조성 덕분에 스탑을 거래소 네이티브 주문에 맡길 수 있습니다 — 스탑이 뒤로
물러나는 일이 없으므로 정정(amend)만 하면 되고 취소 후 재등록이 필요 없습니다.

숏 포지션 상태 기계:
```
진입 → [스탑 = 진입가 + 1.0×ATR]
     → 2R 도달 시 절반 익절 → [스탑 = 본전]
     → 이후 봉 마감마다 추적: 스탑 = min(현재 스탑, 종가 + 2.0×ATR)
     → STOP / TIME 중 먼저 오는 것
롱은 손절 1.5×ATR, 추적 3.0×ATR, BB 중앙선 청산 추가
```

## 4. 자동매매 아키텍처

### 4.1 가장 중요한 설계 결정 — 결정 코어를 백테스트와 공유합니다

`src/live_core.py` 하나가 진입 계획·포지션 개시·봉 마감 갱신·신호 스캔을 정의하고,
**백테스트 엔진(`frontier_engine.run`)과 실거래 트레이더(`live/trader.py`)가
둘 다 이 파일을 호출합니다.**

```
src/live_core.py
  remaining_risk(p)                       남은 위험
  plan_entry(symbol, side, atr, wealth, opens, positions, config, costs, ...)
  open_position(side, ts, signal_ms, plan, qty, wealth, fee, breakout_level)
  update_on_bar_close(p, row, config)     추적스탑 갱신
  scan_signals(ts, rows, symbols, longs, positions, setups, config)
  btc_bull_at(row)                        SMA200 레짐
  apply_tp_fill = mark_partial_taken      2R 부분익절 → 본전 전환
```

I/O 없음, 난수 없음, 시계 없음 — 전부 인자로 주입합니다.
이렇게 하지 않으면 백테스트와 실거래가 시간이 지나며 서서히 달라지고,
그때는 어느 쪽이 맞는지 알 방법이 없습니다.

### 4.3 4시간 경계 시퀀스 (순서가 중요합니다)

```
1. 체결 동기화       거래소 체결을 로컬 상태에 반영
2. 정합성 검사       불일치 시 HALT — 절대 자동 치유하지 않음
3. 봉 갱신           추적스탑 단조 갱신
4. 청산 규칙 평가
5. 신호 스캔
6. 청산 실행         (다음 봉 시가)
7. 진입 실행         canonical 순서로 순차, 진입마다 자산 재조회
8. 보호 주문 등록    SL / TP
9. 스탑 정정
10. 저널 기록
```

**7번의 "진입마다 자산 재조회"는 실제 버그를 고친 결과입니다.** 슬리피지가 즉시
미실현 손실로 잡히므로(100,000 → 99,985.07) 봉 시작에 한 번만 자산을 읽으면
같은 봉의 나중 진입이 과대 산정됩니다.

### 4.4 안전 규칙

- **개인키는 환경변수 `LIGHTER_API_PRIVATE_KEY`로만** 읽습니다. 설정 파일에 두지 않습니다.
- **실거래는 `--mode live` + `--i-understand-this-places-real-orders` 둘 다** 필요합니다.
  기본 모드는 `shadow`(결정만, 주문 없음)입니다.
- **정합성 불일치는 HALT**입니다. 진입을 멈추고 보호 주문은 유지한 채 사람을 부릅니다.
  자동 치유는 없습니다.
- 멱등성은 결정적 `client_order_index`로 확보합니다. 저널은 추가 전용입니다.

### 4.5 알아둘 Lighter 사실 (2026-09-12 확인)

- zk-rollup 무기한 선물 DEX, **Standard 계정 수수료 0/0** (테이커 지연 300ms)
- **SL/TP 트리거는 mark 가격 기준** — 백테스트는 이걸 모형화하지 않습니다
- 교차마진, MMF 1.2~6.0%, 시간당 펀딩(index 가격 기준), 최소 주문 10 USDC
- `Price` 필드가 `c_uint32`
- SDK `lighter-sdk` 1.0.0: `create_order` / `create_sl_order` / `create_tp_order` /
  `modify_order` / `cancel_order`
- ORDER_TYPE: LIMIT=0, MARKET=1, STOP_LOSS=2, TAKE_PROFIT=4, TWAP=6
- TIF: IOC=0, GTT=1, POST_ONLY=2
- ⚠️ **`create_sl_order`는 IOC를 씁니다.** 트리거된 스탑이 한계가에 체결되지 못하면
  **취소**되고 포지션이 무방비로 남습니다. `broker.py` 모듈 독스트링에 기록해뒀습니다.
- ⚠️ **TWAP의 duration 인코딩이 문서에 없고 SDK 헬퍼도 없습니다.** 추측이 필요합니다.

## 5. Stage-1 게이트 — 통과했습니다

1단계(그림자 실행)의 통과 기준: **결정 로그가 같은 기간 백테스트 재실행과 완전 일치.**
일치하지 않으면 구현 버그이고, 이후 어떤 단계의 결과도 해석할 수 없습니다.

`src/live/replay.py`가 이를 오프라인으로 실행합니다.

```
A. SELECTION  (봉, 심볼, 방향)         PASS
B. SIZING     최악 상대오차 4.752e-14   PASS
```

전 구간(2021-01~2026-08) 실행 시 **진입 427건이 전부 일치**하며 수량 상대오차는
부동소수점 수준입니다(2.7e-10).

**게이트 B가 처음에 실패한 원인** — `ReplayBroker.modify_stop`이 설정된 적 없는
`lv.get('ref')`로 주문을 찾으려다 실패하면 폴백 경로로 빠져 **하나의 트리거 값을
모든 포지션에 써버렸습니다.** `_owner` 맵으로 소유권을 명시하고 못 찾으면 예외를
던지도록 고쳤습니다.

**다만 이것은 과거 봉에 대한 재현이며, 실제 체결·지연·mark 트리거가 들어간
실거래 검증이 아닙니다.** 2단계 이후가 필요합니다.

### 6.2 지정가·post-only로 슬리피지를 줄일 수 있는가 — **대체로 아니다**

**(1) 비용의 86%는 스프레드가 아니라 충격입니다.**
평균 half-spread 1.4bp, impact 8.2bp. 패시브로 회수 가능한 건 14%뿐입니다.
BCH는 42bp 중 41.6bp가 충격 — 지정가로 손댈 수 없습니다.

**(2) 패시브 진입은 역선택에 걸립니다.** 실제 진입 427건의 5분봉 경로로 측정:

| 가격개선 | 체결률 | 체결분 평균R | **미체결분 평균R** |
|---:|---:|---:|---:|
| 2bp | 98.1% | 0.267R | **1.247R** |
| 10bp | 93.7% | 0.229R | **1.115R** |
| 20bp | 87.4% | 0.207R | 0.824R |

**미체결 거래의 평균 R이 체결분의 4~5배입니다.** 즉시 달아나 되돌아오지 않는
거래가 곧 이 전략의 승자이기 때문입니다(§2.3의 "수익이 소수의 큰 달에 몰림"과
같은 현상). 10bp를 노리면 27건을 놓치고 그 순손익 합 +127,966 = **전체 순이익의 18%**.

**(3) 패시브 가능한 레그는 7.6%뿐입니다.**

| 레그 | 명목 비중 | 판정 |
|---|---:|---|
| ENTRY | 50.0% | 테이커 필수 (위 2번) |
| STOP | 37.2% | 테이커 필수 — 체결 안 되는 손절은 손절이 아님 |
| **TP2R** | **7.6%** | **패시브 가능 → 채택** |
| BB_MID | 4.9% | 가능하나 이득 작음 |

**채택한 것:** 2R 익절만 post-only 지정가로 전환(`passive_take_profit`, 기본 on).
목표가에 거는 주문이라 역선택이 없고, 안 채워지면 애초에 원하지 않던 체결입니다.
post-only가 거부되면 기존 트리거 주문으로 폴백합니다.

이 과정에서 버그 하나를 같이 고쳤습니다 — 상주 지정가는 **분할 체결**될 수 있는데
기존 코드는 1%만 줄어도 본전 스탑을 걸었습니다. 2R 레그가 다 채워질 때까지
기다리도록 바꿨습니다.

## 7. 겪은 문제와 해결 — 재발 방지용

### 7.1 데이터·측정 관련

| 문제 | 원인 | 교훈 |
|---|---|---|
| 벤더 결과 CSV 덮어씀 | `run_backtest.py` 재실행 시 ULP 부동소수점 드리프트 | 감사된 산출물은 그대로 커밋하고 재생성하지 말 것 |
| 월간 연 경계 0.04%p 불일치 | 우측 경계 타임스탬프를 달력 기준으로 binning | `(이전 월말, 당월말]` 규약 고수 |
| Lighter 시장 목록에서 SOL 누락 | **WebFetch 요약이 두 번이나 SOL을 빠뜨림** | **원시 JSON을 직접 받아 확인할 것.** SOL은 market_id 2에 존재 |
| VWAP 절감 +6.89bp 허상 | 독립 스냅샷 재비교 = 같은 주문 반복 사용 | 소진·재충전을 모형화해야 함 → +1.98bp |
| 패치 스크립트가 조용히 무적용 | 슬라이스 식 안의 중첩 따옴표 구문 오류 | 패치 후 **반드시 변경 확인** (assert) |
| Binance 451 | 지역 제한 | `www.binance.com`이 같은 `/fapi` 경로 서빙 |

### 7.2 ⚠️ Binance `www` 호스트에 대한 경고

`fapi.binance.com`은 제한 지역에서 451을 반환합니다. `www.binance.com`이 같은
`/fapi/v1/depth`와 `/fapi/v1/klines`를 서빙하며 접근됩니다
(2026-09-12 확인: 응답 형식 동일, 1000레벨, 최우선호가가 Lighter mark와 0.5bp 차이).

**그러나 이 호스트는 Binance 공개 API로 문서화된 곳이 아닙니다.** 언제든 바뀔 수
있으므로, 실행 첫 분에 로그에 봉이 찍히는지 확인해야 합니다.
두 호스트 모두 막히는 경우는 검증하지 못했습니다 — **확실하지 않음**.

코드는 451/403과 네트워크 오류를 다르게 다룹니다. 451은 그 호스트가 정책상 계속
거부한다는 뜻이므로 재시도 없이 즉시 다음 호스트로 넘어갑니다. 재시도하면 지수
백오프 예산(2+4+8+16초)을 다 쓴 뒤에야 살아있는 호스트에 닿고, 그걸 매 봉 반복합니다.

### 7.3 코드 버그 (전부 수정됨)

- **Stage-1 게이트 B**: `ReplayBroker.modify_stop`이 설정된 적 없는 `ref`로 매칭
  실패 → 폴백이 하나의 트리거를 모든 포지션에 기록. `_owner` 맵 + KeyError로 수정.
- **브로커 심볼 공간 불일치**: DryRun은 전략 심볼, Lighter는 Lighter 심볼로 키잉.
  `market.symbol`로 통일.
- **청산이 이전 봉 종가에 체결**: 진입과 같은 `opens` 맵을 공유하도록 수정.
- **신호→진입 한 봉 어긋남**: 방금 마감한 봉에서 `pending`을 세우고 같은 호출에서 소비.
- **자산을 봉당 한 번만 조회**: 슬리피지가 즉시 미실현 손실로 잡혀(100,000 →
  99,985.07) 같은 봉의 나중 진입이 과대 산정. 진입마다 재조회로 수정.
- **분할 체결 시 조기 본전 스탑**: 2R 레그가 다 채워질 때까지 대기하도록 수정.
- **재시작 시 `equity 0.00` 보고**: 자리표시자 0이 계좌가 날아간 것처럼 보임. 실제 자산 보고로 수정.

### 8.2 페이퍼 4주 실행 — 사용자 머신에서 이어받아야 합니다

원격 세션 컨테이너는 비활성 시 회수되므로 **4주 연속 실행을 거기서 호스팅할 수
없습니다.** 코드는 준비됐고, 사용자 머신에서 실행해야 합니다.

```bash
git clone https://github.com/kimka3/bb-squeeze_v15
cd bb-squeeze_v15
git checkout claude/nice-albattani-s4qjto
pip install -r requirements.txt

./scripts/run_paper.sh                            # 28일, 크래시 시 자동 재시작
tail -f live_state/paper.log                      # 진행 확인
python3 src/live/run.py --mode paper --report     # 중간 측정치
```

**4주 실행이 4시간 실행과 다른 점 — 설계에 반영했습니다.**

- **종료 시점을 기간이 아니라 절대 시각으로** 받습니다(`--until ISO8601`).
  기간으로 주면 재시작마다 시계가 리셋돼 실행이 영원히 안 끝납니다.
  `run_paper.sh`가 최초 1회만 `live_state/paper_until.txt`에 적습니다.
- **재시작이 같은 봉을 재처리하지 않습니다.** `trader.last_bar_ms`가 막고,
  신선도 가드가 4시간보다 오래된 봉을 거부합니다.
- **시작 직후 밀린 봉을 따라잡습니다.** 없으면 재시작마다 최대 4시간을 버립니다.

⚠️ **상태는 `live_state/`에 있고 이 디렉터리는 `.gitignore` 대상입니다.**
측정 결과물이 거기 있으므로 **보존해야 실행이 이어집니다.**

### 8.3 4주 페이퍼의 목적 — 무엇을 보려는 것인가

1. **슬리피지 분포.** §6의 수치는 전부 **스냅샷 1회**입니다. 시간대·변동성에 따라
   달라지므로 4주간 반복 측정해 분포를 얻는 것이 2단계의 핵심 목적입니다.
2. **mark 트리거 실제 동작.** 백테스트는 모형화하지 않습니다.
   `trigger → fill` 간격이 실제로 몇 bp인지.
3. **post-only 익절의 체결률.** 거부율과 폴백 빈도.
4. **펀딩 실측.** 백테스트는 Binance 펀딩을 썼습니다.
5. **깊이 소진 경보.** 전략이 원한 크기를 호가가 감당 못 한 횟수.

### 8.4 열려 있는 질문

- **자산 규모를 얼마로 갈 것인가 — 가장 중요한 열린 질문.** §6.1b가 이 전략의
  최대 제약입니다. 100,000에서 CAGR 31.14%, 400,000에서 11.92%, 1,000,000에서는
  마이너스입니다. 절대 수익은 자본이 클수록 커지지만 Calmar는 무너집니다.
  규모를 줄이면 제외 종목 목록도 달라집니다(§6.3).
- **Hyperliquid 하이브리드?** 메이저는 Lighter, 알트는 Hyperliquid이 유리합니다.

- **TWAP duration 인코딩.** 이득이 0.45bp라 현재는 정당화되지 않지만,

## 9. 남는 위험 — 반드시 함께 읽을 것

- **최대 낙폭 -33.15%(수수료 0) / -36.01%(Binance)는 5분봉 종가 기준**입니다.

- **교차마진·ADL은 백테스트에 없던 위험**입니다. 다른 계정 활동과 섞지 마십시오.

- 위험 2%는 이 표본에서 CAGR/|MDD|가 가장 높았을 뿐, **미래 최적 위험으로
  검증된 값이 아닙니다.**
- **Stage-1 게이트 통과는 과거 봉 재현**이며 실거래 검증이 아닙니다.
- 이 프로젝트는 아키텍처·검증 작업이며, **전략의 미래 수익을 보증하지 않습니다.**

## 11. 요약 — 한 문단으로

BB Squeeze A안(4시간봉, 숏 편중, 11종목)의 거래당 위험을 1.25%에서 2%로 올렸고
(CAGR 44.75% / MDD -33.15%, 수수료 0 가정), Lighter 자동매매를 백테스트와 결정
코어를 공유하는 구조로 구현해 과거 427건 진입이 봉·심볼·방향·수량까지 일치함을
확인했습니다. 실행 비용을 실측한 결과 **백테스트의 2bp 가정은 자산 5,000에서만
성립하며 100,000에서는 8.8bp로 CAGR이 14%p 깎입니다.** 비용의 86%가 충격이라
지정가로는 손댈 수 없고(익절 레그 7.6%만 post-only로 전환), 분할 체결도 얇은
종목일수록 호가가 되살아나지 않아 0.45bp에 그칩니다. **가장 효과적인 조치는
BCH 한 종목을 비용 근거로 제외하는 것이었고(9.06 → 5.33bp), 이 결정이 거래소
선택까지 바꿔 Lighter가 다시 최적이 됐습니다.** 현재 2단계 페이퍼 4주 실행을
준비 완료했으며, 목적은 지금까지의 스냅샷 1회 측정을 **분포**로 바꾸는 것입니다.
