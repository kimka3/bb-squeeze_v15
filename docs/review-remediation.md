# 검토 후 구현 결과와 남은 실행 조건

이 문서는 `docs/review-findings.md`의 문서 검토 이후 실제 코드를 확인하고 수정한 결과다. 기존 전략 성과를 새로 산출한 보고서가 아니다. 사용자의 VPS가 미준비 상태이므로 **실제 4주 캠페인은 시작하지 않았다. 시작·종료 날짜도 아직 없다.**

## 구현한 변경

| 검토 항목 | 실제 변경 | 범위 |
|---|---|---|
| 무유동성·부분 청산 | 빈 호가에서 가짜 체결을 생성하지 않고, 가시 잔량만 체결한다. 신호 청산 전 보호 주문을 먼저 취소하지 않으며 남은 포지션을 유지한다. | 페이퍼 및 공유 실행 조정 계층 |
| IOC 손절 잔량 | 취소된 스탑의 잔량을 감지하고 신규 진입을 HALT한다. 신선한 가격에서 확인된 잔량의 축소를 재시도하고 보호를 복구한다. 교체 스탑은 새 주문 세대 ID를 쓴다. | 모의 주문으로 장애 검증 |
| 보호 등록·재시작 | 의도·제출 결과·체결·보호 등록을 영속화한다. 모의 브로커는 동일 ID의 결과를 디스크에서 조회하며 불명확한 주문을 맹목적으로 재전송하지 않는다. | 실제 거래소 확인 연동은 미완료 |
| TP 부분체결 | 명시적 누적 TP 체결량으로 완료를 판단한다. 일반적인 수량 감소를 TP로 추정하지 않는다. | 원래 TP 비율과 ATR 거리는 유지 |
| post-only 익절 | 기본 `crossed_depth` 모형은 목표가 터치만으로 체결하지 않고 목표를 통과한 반대측 가시 잔량으로 제한한다. `observe_only` 선택도 가능하다. | 실제 maker 체결률은 미관측 |
| 가격·주문 참조 | 실제 모의 체결가에 원래 ATR 거리를 적용한다. 취소 실패한 고아 보호 주문을 잊지 않고 추적한다. | 공유 전략 코어 변경 없음 |
| 데이터 공백 | 중복·누락·비정상 봉, 종목 간 시각 불일치, 잘못된 mark를 거부한다. 늦은 신규 진입을 막고 여러 봉의 공백은 명시적으로 기록하고 전략 처리를 HALT한다. | 누락 체결을 소급 생성하지 않음 |
| 빠른 보호 관리 | 봉 다운로드와 관측 작업은 별도 읽기 전용 스레드로 처리한다. 모의 poll 일부 실패 후에도 영속화된 체결을 대조하되 오래된 가격으로 잔량을 처리하지 않는다. | 실제 거래소의 연속 이벤트 스트림은 미구현 |
| 용량 관측 | 신호가 없는 동안에도 양방향 호가 원자료와 당시 모의자산 기반 비용 추정치를 주기적으로 보관한다. | 스냅샷 워킹 모형이며 실제 자기 충격 아님 |
| 펀딩 | index 관측과 원시 펀딩 응답을 보존한다. 공개 API의 명시되지 않은 부호·단위를 추측해 현금에 반영하지 않는다. 종료 포지션의 누계도 보존한다. | 미해결 정산이 있으면 성과 불완전 표시 |
| 운용 감독 | UTC 고정 28일, 설정·소스·의존성 동결, OS 잠금, 유한 재시작, 상태·종료 기록, systemd 배포를 추가했다. | 실제 Linux 서비스 기동은 VPS에서 검증 필요 |
| 보고서 | 시장 원자료와 모의 체결을 구분하고, 오프라인 상태·보고서 읽기를 지원한다. 누적 오류·관측 수와 마지막 성공 시각을 남긴다. | 4주 종료를 실거래 통과로 간주하지 않음 |

기존 `live_core.py`, 백테스트 엔진, 감사된 `results/cases` 산출물은 변경하지 않았다. Lighter·BCH 제외·개별 위험 2%·총 초기 위험 4%·canonical 순서를 유지한다. 운영 기본값은 이번 구현의 설정이며 미래 수익이나 실행 가능성의 실측 보장이 아니다.

## 실거래 기능에 대한 중요한 제한

기존 Lighter 어댑터는 주문 제출 응답 후 실제 체결 조회 없이 수량·가격을 채운 `Fill`을 반환했다. 현재는 이런 결과를 체결로 신뢰하지 않도록 **실거래 주문 제출 전에 차단**한다. 페이퍼 실행에는 거래소 키나 입금이 필요 없다.

실계좌를 열려면 인증된 주문 종결 상태·부분체결·체결 원장·활성 보호 주문 확인, 응답 유실 복구, 실제 수수료·펀딩·증거금 대사를 구현하고 별도 검증해야 한다. 현 코드가 실거래 가능하다고 해석해서는 안 된다.

## 펀딩 검토 정정

이전 주소의 검색 캐시를 근거로 mark 기준을 지적했던 부분은 정정했다. 현재 유효한 [공식 Funding 문서](https://docs.lighter.xyz/trading/funding)의 지급액 식은 index 기준이며 인수인계 내용과 일치한다. 공개 시장 메타에서 `index_price`가 실제 존재하는 것도 확인했다. 반면 [공식 Funding 응답 스키마](https://raw.githubusercontent.com/elliottech/lighter-python/main/docs/Funding.md)는 `timestamp/value/rate/direction`의 의미 설명이 비어 있으므로 부호·단위를 확정하지 않았다.

미해결 펀딩이 있으면 `performance_complete=false`, `equity_excludes_unresolved_funding=true`다. 이때 잔액·낙폭은 누락 비용을 포함한 완전한 순성과가 아니다. 데이터 공백도 별도로 보고서에 표시한다. 이번 수정에서 새로운 CAGR·MDD를 만들어 제시하지 않았다.

## 실행 검증

이번에 실제 수행한 검사 수치이며 인수인계 성과의 인용과 구분한다.

- 고정 가상환경: Python 3.11.5, NumPy 2.3.5, pandas 2.2.3.
- 로컬 전체 테스트: 130개 통과. 주문 장애·영속화·부분체결·보호 복구·지정가 모형·감독기·데이터·런타임 검사를 포함한다.
- 고정 의존성 환경의 전체 기간 Stage-1: 현재 10종목 유니버스에서 진입 393건 모두 일치, 수량 최대 상대오차 1.562e-10, PASS. 원문 427건은 11종목 기준이므로 서로 다른 유니버스의 건수를 혼동하지 않는다.
- Bash 실행 스크립트 구문 검사 통과.
- 공개 데이터 사전점검: 현재 PC에서 10종목의 봉·mark·양방향 호가를 읽었다. 전체 준비 판정은 로컬과 서버 시각 차이가 새 운영 한도를 초과해 차단됐다. 임계값을 늘려 통과시키지 않았다.
- Linux CI는 `.github/workflows/paper-safety.yml`에서 Python 3.11·3.12의 테스트와 Stage-1 일부 구간을 수행한다. 실제 판정은 해당 커밋의 GitHub Actions 결과를 확인한다.

실제 VPS 사전점검·systemd 실행·4주 관측·실계좌 체결은 아직 수행하지 않았다. 서버가 준비되면 [페이퍼 운용 절차](paper-operations.md)를 따라 설치와 점검을 먼저 수행한다.

## 후속 검증으로 남긴 것

- 인증된 실거래 어댑터와 실제 체결·펀딩 원장의 대조.
- maker 대기열, 자기 주문의 지속 충격, 실행 지연의 실제 분포.
- 명시되지 않은 공개 펀딩 응답 의미를 정산 근거와 연결.
- 급등 시 상관된 숏 동시 청산, 증거금·ADL·담보 위험.
- 운용액 증가에 따른 동적 비용을 반영한 별도 백테스트 및 표본 밖 전략 검증.
- 운영자가 승인한 외부 경보 채널 연결. 현재 상태 파일과 서비스 로그가 경보 근거이며 외부 전송을 설정하지 않았다.

이 항목들을 이번 코드 변경만으로 해결됐다고 주장하지 않는다. VPS 설치와 페이퍼 측정으로 우선 수집할 증거를 구체화했다.
