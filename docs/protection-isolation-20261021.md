# 보호 작업 격리와 손절 주문 갱신 — 2026-10-21

이 변경은 매매 신호, 종목, 진입·손절·익절 규칙, 위험비율과 승인 자본을 변경하지 않는다. 지원하지 않는 이력 한 건이 다른 종목의 보호 작업까지 막는 문제와, 확정 미전송된 손절 갱신 주문의 수량이 부분 익절 이후 낡아지는 문제를 수정한다.

## 지원하지 않는 이력과 보호 작업의 분리

기존에는 거래·펀딩 이력을 해석하는 과정에서 지원하지 않는 유형을 만나면 계좌 상태 조회가 예외로 끝났다. 같은 조회에 의존하는 다른 종목의 손절 조정과 위험 감축도 진행하지 못할 수 있었다.

이제 공통 스키마, 계좌 귀속, 식별자, 종목, 시각과 수량·금액 형식을 검증할 수 있지만 경제적 의미만 지원하지 않는 기록을 구분한다. 현재 대상은 지원하지 않는 거래 유형과 펀딩 방향이다. 해당 원문과 진단 정보를 `account-ledger.sqlite`의 `history_quarantine`에 보존한다. 페이지의 지원 기록, 격리 기록과 다음 커서는 같은 트랜잭션에서 저장한다. 같은 ID의 내용 변경이나 지원 기록과 격리 기록의 충돌은 자동 덮어쓰지 않는다.

격리된 기록을 정상 거래·펀딩으로 변환하거나 손익·수수료·펀딩 합계에 넣지 않는다. `historical_issues`, `historical_evidence_complete=false`와 `performance_complete=false`로 한계를 표시하며, 엄격한 장부 검증은 통과시키지 않는다. 수집 페이지를 모두 읽었다는 상태와 기록의 경제적 의미를 검증했다는 상태는 별개다.

지원하지 않는 이력이 있으면 계좌 전체의 신규 진입은 지속되는 `HALT`로 차단한다. 해당 종목은 확인된 위험 관리 가능 종목에서 제외하여, 불명확한 잔량이나 정산을 추측해 주문·취소·청산하지 않는다. 다른 종목은 현재 계좌 잔량, 소유 주문·체결과 보호 주문이 독립적으로 일치할 때 기존 보호·감축 처리를 계속할 수 있다. 확정봉 처리, 재시작 복구와 고아 주문 정리도 이 종목별 제한을 따른다. 이는 문제 종목의 자동 복구나 정상 판정이 아니다.

승인 배정 자산을 계산할 수 없는 동안 새 손익을 만들어내지 않는다. 보호 진단에 필요한 자산은 최신 실제 계좌 자산을 승인 초기 자본으로 제한한 값만 사용하고, 배정 자산 검증 미완료를 표시한다. 해당 종목과 계좌 장부는 원문에 근거한 수동 대조가 필요하며 기존 `HALT`와 `ENTRY_PAUSED`를 자동 해제하지 않는다.

## 확정 미전송 손절 갱신과 부분 익절 경합

기존 갱신은 새 손절 주문의 보호를 확인한 뒤 옛 손절 주문을 취소한다. 그러나 새 주문이 전송 전에 확정 거절된 상태에서 TP가 체결되면, 재시도하려던 주문의 고정 수량이 실제 잔량보다 커질 수 있었다. 원 ID의 terms를 바꾸지 않는 검증 때문에 갱신이 반복 거절되고 보호가격 조정도 지연될 수 있었다. 전송되지 않은 갱신 주문 때문에 기존의 정상 손절까지 보호 미완료로 분류되는 문제도 있었다.

수정 후에도 주문 결과 불명과 확정 미전송을 엄격히 구분한다. 저장된 결과가 없고 `not_submitted`이며 `retryable=true`라는 명시적 증거가 있을 때만 다른 ID를 예약할 수 있다. 수량이나 보호가격이 같으면 원래의 동일 ID 재시도 경로를 유지한다. 결과 불명, 전송 시작·접수, 비재시도 거절은 이 교체 경로를 허용하지 않는다.

현재 잔량과 포지션 주기, 계좌·시장·방향, reduce-only SL, 보호가격의 비완화와 기존 손절의 유효한 보호를 확인한다. 새 수량은 원 수량보다 늘리지 않는다. 원래 intent와 결과는 변경하지 않고, 새 ID와 연결 근거를 별도로 기록한다. 새 SL의 전체 잔량 보호, 가격과 연장된 만료를 확인한 뒤에만 기존 SL을 취소한다. 기존 SL이 같은 소유 주기의 전체 잔량을 보호한다면 확정 미전송 갱신만으로 보호가 없다고 오판하지 않는다. 미해결 갱신이 남아 있는 동안 신규 진입 제한은 유지한다.

기존 SL이 만료되거나 보호 기능을 잃은 경우에는 미전송 갱신을 유효한 보호로 간주하지 않는다. 초기 SL 설치가 확정 미전송으로 대기하는 경우와 갱신을 구분하여, 후자가 검증된 현재 잔량의 `PROTECTION_LOST` reduce-only 비상청산을 가로막지 않게 한다. 이 경로가 실행되어도 HALT를 자동 해제하지 않는다.

## 저장 순서와 재시작

1. 기존·신규 ID와 목표 terms를 포함한 `replacement_plan`을 실행기 스냅샷에 먼저 저장한다.
2. `execution.sqlite`의 한 트랜잭션에서 새 intent와 명시적 미전송 상태를 예약하고 `intent_supersessions(old_coi, new_coi, proof)` 연결을 저장한다.
3. 실행기가 새 ID를 참조하도록 저장한 뒤 실제 전송 경로로 진행한다. 실제 전송 직전에는 미전송 상태를 `dispatching`으로 바꾸므로, 그 이후 중단은 결과 불명으로 남긴다.
4. 재시작 시 저장된 계획·연결을 동일 ID로 완료한다. 저장 실패는 전송을 허용하지 않으며, 이미 연결된 옛 ID는 엔진과 저장소 모두 재전송을 거부한다.

새 연결 전후, 전송 전후에 중단돼도 원 ID를 버리거나 새로운 주문을 무조건 추가하지 않는다. 추가 TP로 잔량이 또 줄면 확정 미전송 조건에 한해 다음 연결을 만들고 앞선 ID들을 모두 유지한다. 포지션이 청산되면 기록된 ID별로 확정 종료·미전송 증거를 확인한다. 확정 미전송이라고 저장했던 ID가 나중에 거래소 주문·체결로 나타나면 모순으로 차단한다. flat 상태나 새 주문 성공으로 이 모순을 무시하지 않는다.

## 유지한 조건과 검증 한계

- 기존 실제 장애 복구의 전체 poll·service 연속 3회, 최소 120초 안정 구간, 주기 사이 최대 90초 조건을 유지한다. 정상 봉 전환과 기존 진입 허용시간도 바꾸지 않는다.
- 공통 스키마·계좌 귀속·식별자·수량·금액을 검증할 수 없는 기록은 종목만 추측해 격리하지 않고 기존처럼 강하게 차단한다. 저장 오류, 외부 노출, 주문 결과 불명도 정상 게시 지연으로 취급하지 않는다.
- 격리는 지원하지 않는 기록의 경제적 의미를 구현한 것이 아니다. 해당 기록의 손익·수수료·펀딩과 영향 종목의 장부 대조는 미확인으로 남는다. 수동 대조 없이 자동 해제하지 않는다.
- 검증은 가상 거래소와 로컬 SQLite를 이용한다. SL 경합은 수정 전 실패를 재현했으며 부분 TP, 재시작, DB 트랜잭션 실패, 추가 TP, 만료, 기존 HALT와 뒤늦은 옛 ID 등장을 회귀 시험한다. 이 문서 자체는 VPS 반영 또는 실제 계좌에서 같은 사례가 발생해 검증됐다는 증거가 아니다.
- 신규 SQLite 테이블과 스냅샷 계획을 배포 백업에 포함한다. 새 상태를 기록한 뒤에는 해당 스키마와 상태를 모르는 이전 바이너리로 검증 없이 되돌리지 않는다.
- 확정 미전송과 대체된 ID도 뒤늦은 거래소 등장 여부를 조회한다. 누적 ID 수에 따른 조회 비용 증가는 관찰 대상이며, 이번 변경이 요청량 상한이나 보호용 여유를 완화하지는 않는다.
