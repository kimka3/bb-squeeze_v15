# 이력 수집 및 게시 지연 처리 — 2026-10-21

이 변경은 거래 신호, 종목, 진입·손절·익절, 위험비율, 승인 자본을 변경하지 않는다. 정상 운영 중 상세 거래 이력이 주문·계좌보다 늦게 게시되는 경우와 실제 소유권 불일치를 구분한다.

## F-4: 최근 이력과 반복 전체 대조

`AccountLedger.collect()`는 최근 이력을 먼저 수집하고 별도로 캠페인 시작까지의 전체 대조를 계속 반복한다. 최근 구간의 경계 이전에 뒤늦게 게시된 거래·펀딩도 전체 대조에서 다시 방문한다. 이전 기록은 삭제하지 않으며 같은 ID의 내용 변경은 자동 덮어쓰지 않고 오류로 처리한다.

수집기 호출당 최근 조회는 종류별 최대 2페이지, 전체 대조는 종류별 최대 1페이지다. 전체 대조는 종류별 60초 시간 구간당 한 번만 진행하며, 추가 조회 전 21회분 여유를 확인하여 보호 작업용 20회분을 남긴다. 이는 이 코드에서 선택한 운영 상한이다. 실제 HTTP 재시도는 기존 전송 계층의 별도 제한을 따르므로 `per_call_requests`는 실제 HTTP 횟수가 아닌 논리적 조회 횟수다. 기존 55회/60.1초 예산과 진입 전 24회·전송 직전 20회 여유는 유지한다.

각 페이지의 거래·펀딩과 다음 커서는 같은 SQLite 트랜잭션으로 저장한다. 재시작 시 중간 페이지부터 이어가며 전체 조회를 한 번에 100페이지로 제한하던 경로를 사용하지 않는다. `head_complete`와 `full_audit_complete_through_ms`를 분리한다. 일부 페이지만 읽고 과거 전체를 확인한 것으로 표시하지 않는다. 원래의 단독 `history()` 함수는 기존 감사 도구 호환성을 위해 유지한다.

최근 조회와 주문·계좌 대조가 완료되면 과거 전체 대조는 배경에서 계속할 수 있다. 따라서 매우 늦게 게시된 과거 외부 왕복 거래나 기존 기록 정정은 다음 전체 대조에서 발견될 수 있으며 매 진입 직전에 과거 전체를 다시 검사하는 것은 아니다. 현재 잔량의 소유 주문 대조와 승인 자본 상한은 계속 적용한다. 발견된 외부 거래·정정은 정상으로 덮지 않는다.

공식 `/trades` 문서는 cursor와 내림차순 정렬을 제공하지만 시작·종료 timestamp 필터를 제공하지 않으며 `from`의 경계 의미를 명시하지 않는다. 따라서 `from`을 시간으로 추측해 사용하지 않는다. `/positionFunding`는 시간 범위를 지원하며 기존 운영에서 검증한 초 단위 경계 패딩과 로컬 범위 검사를 유지한다.

공급자의 최대 게시 지연·커서 스냅샷·보존 기간 보장은 확인되지 않았다. 반복 전체 대조는 공급자가 기록을 계속 반환하고 페이지 조회가 진전된다는 조건 아래 지연 기록을 회수한다. 거래소가 기록을 반환하지 않거나 삭제하면 복구를 보장할 수 없다. 완주 시각도 공급자의 절대적 데이터 완전성 인증은 아니다.

## F-3: 엄격한 소유 주문 대조를 통과한 지연만 대기

게시 지연으로 처리하려면 주문의 계좌·종목·방향·주문 ID·주기 소유권이 확인되어야 한다. 상세 거래 수량과 금액은 누적 주문 체결의 엄격한 부분집합이어야 하고, 소유 주문 누적으로 계산한 노출이 실제 계좌 잔량과 정확히 일치해야 한다. 설명되지 않는 수량 변화, 외부 거래, 전송 결과 불명, 잘못된 주기, 금액 불일치, 저장·스키마 오류는 이 경로에서 자동 해제하지 않는다.

`publication_pending` 동안 신규 진입은 차단하며 미전송 진입 후보는 폐기한다. `risk_verified_symbols`는 확인된 기존 노출의 보호·감축에만 사용한다. 익절 주문의 완전 체결 증거로 부분 익절 후 보호를 조정할 수 있지만 단순 잔량 감소로 익절을 추정하지 않는다. 상세 청산 이력의 지연이 자본을 가짜로 줄이지 않도록 대기 상태의 위험 평가에는 검증된 소유 주문의 누적 체결 금액을 사용하며 실제 계좌 자산을 상한으로 둔다. 이 상태에서 신규 진입이나 성과 완전성 인증은 허용되지 않는다.

지연 중에도 확정봉과 기존 포지션의 위험 관리를 처리하므로 봉 처리 정체 때문에 별도 데이터 누락이 만들어지지 않는다. 이력이 정상화된 뒤에도 기존 전체 poll·service 연속 3회, 최소 120초 안정, 주기 사이 최대 90초 조건을 그대로 통과해야 한다. 자동 복구가 소유한 `EXCHANGE_PAUSED`만 해제한다. 수동 `ENTRY_PAUSED`와 `HALT`는 해제하지 않는다. 실제 계좌 응답 자체가 오래된 경우까지 게시 지연이라고 추측하지 않는다.

## 검증과 배포

가상 거래소를 이용해 오래된 지연 기록, 동일 시각 다중 페이지, 100페이지 초과 수집, 커서 이동, DB 재시작·트랜잭션 롤백, 예산 소진, 지속 게시 지연·정상화, 외부 거래와 미확정 주문, 보호 잔량 처리를 시험한다. 실거래에 강제 주문이나 장애를 발생시키지 않는다.

배포 시 기존 이벤트·주문·펀딩·캠페인·설정과 신규 체크포인트의 유효성을 각각 대조한다. 유지보수로 만든 중지 표시만 검증 후 해제한다. 새로운 실행기가 시작되어 스키마가 추가된 뒤에는 검증 없이 예전 바이너리로 되돌리지 않는다.
